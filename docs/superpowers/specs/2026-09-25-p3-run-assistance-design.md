# P3 实跑辅助与验收加固

## 范围

本阶段完成独立实跑辅助的用户体验和验收基础：目标/实测步频提示、可选语音播报、真实记录导出、失败状态，以及 Android 生命周期和响应式界面的结构检查。不实现定位注入、传感器注入、LSPosed/Xposed 或第三方应用兼容性。

## 数据边界

`recordings` 只保存真实 GPS、逐步传感器和累计计数器观察；`simulations` 只保存合成历史。实跑导出只读取当前真实记录文件，模拟导出只读取模拟历史。导出文件由用户通过 Android `CreateDocument` 选择目标位置，不自动分享或上传。

应用私有原始 CSV 保持现有表头，避免破坏 S7→S6 桥接和旧文件读取；用户主动导出的 CSV 增加 `# provenance=real_observation` 元数据，并保留 `location_age_s` 字段。JSON/GPX 导出保留真实观测来源和 GPS 新鲜度语义；没有合格 GPS 数据时拒绝导出，不用模拟坐标填充。

## P3 提示

在 `sim-core` 增加无 Android 依赖的提示决策器。输入包括目标步频、当前估计步频、步频可用性、GPS 新鲜度和单调时间；输出为去抖后的提示意图，例如等待传感器、提高/降低步频、保持、GPS 过期。决策器不修改 cadence estimator，也不把累计步数用于实时步频。

Android 层负责把提示意图映射为本地化文本和 `TextToSpeech` 播放。语音按最短间隔去重，服务停止、初始化失败或系统不支持时安全降级为 UI/通知文本。后台服务只播报真实观测状态，不播报仿真值。

## 实跑导出

记录页增加导出入口和格式菜单，使用 `CreateDocument` 支持 CSV、JSON、GPX。只允许选择最近一个已停止的真实 CSV，并显示样本数、持续时间、GPS 新鲜度概况和 provenance。正在写入的文件不得导出，空文件、无有效 GPS、解析失败和目标不可写都给出错误状态。

CSV 导出保留原始真实观测字段。JSON 使用真实样本、真实 GPS 轨迹和明确的 `real_observation` 标记。GPX 只由真实纬经度和有效 ISO-8601 时间戳生成；不添加合成点。

## 测试与验收

- `sim-core` JVM 测试覆盖提示去抖、不可用/过期状态、目标偏差和实时步频来源。
- Python/结构检查覆盖 provenance、真实/模拟目录隔离、资源完整性和注入 API 禁止项。
- Android lint/debug APK 继续由 GitHub Actions JDK 17/21 流程执行。
- UI 检查覆盖小屏、横屏、大字体、深色/浅色资源和通知动作的可达性；没有连接设备时明确记录未完成真机验收。
- 不作“误差小于 5 步/分”的声明，直到完成三次户外人工参考计数并汇总结果。
