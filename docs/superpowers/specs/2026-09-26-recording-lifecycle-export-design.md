# 记录生命周期与安全导出设计

日期：2026-09-26
状态：已确认，实施中

## 1. 目标与边界

本阶段硬化真实跑步记录的生命周期和导出资格判定，确保用户只能导出已经完整关闭的真实观测文件。模拟历史继续独立存放在 `simulations`，真实记录继续独立存放在 `recordings`。

本阶段不实现系统级定位/传感器注入，不改变 S7 原始 CSV 表头，不把模拟坐标补入真实记录，也不把心跳超时当作文件完整性的证明。

## 2. 状态模型

记录状态由服务写入应用私有的 `recorder_status` 偏好，并由 UI 和导出逻辑读取：

- `IDLE`：没有正在记录，也没有待处理的停止操作。
- `ACTIVE`：文件已创建、CSV 表头已写入、writer 可用，采集已经开始。
- `STOPPING`：停止流程已开始，仍禁止导出。
- `STOPPED`：监听器已解除、writer 已刷新并关闭，文件可进入严格解析和导出。
- `ERROR`：服务或关闭流程异常，文件不得导出，需显示错误状态。

状态更新顺序必须与资源状态一致：创建文件并成功写入表头后才能进入 `ACTIVE`；停止时先进入 `STOPPING`，再解除 GPS/传感器监听，刷新并关闭 writer，最后写入已关闭文件名和 `STOPPED`。任何步骤失败都写入 `ERROR`，并清除可导出候选。

状态字段至少包括：状态、当前文件名、已关闭文件名、状态更新时间、最后心跳、错误摘要。已有目标步频、步频、GPS 和计数器字段保持兼容。

## 3. 文件与并发规则

真实文件名继续使用 `recording-[0-9]+.csv`，目录固定为应用私有 `files/recordings`。导出候选必须满足：

1. 文件名通过严格正则校验；
2. 文件位于 canonical 的 `recordings` 目录内；
3. 文件名等于状态中明确记录的已关闭文件名；
4. 状态为 `STOPPED`；
5. 文件在导出前通过 `RealRunExport.parse`；
6. 解析结果满足现有 S7 规则，包括递增时间、至少两行、有效坐标、至少一个新鲜 GPS fix；
7. 状态和文件元数据在读取后再次确认，发现记录重新启动、文件被替换或状态改变则拒绝导出。

停止和导出在同一进程内通过同步临界区/单线程状态更新避免交叉执行。导出只读取已关闭文件，不删除、重写或移动原始记录。用户选择的目标 URI 仍由 `CreateDocument` 提供，写入失败只报告错误，不影响原始记录。

## 4. 异常和进程终止

服务正常停止必须完成关闭流程。若进程在 `ACTIVE` 或 `STOPPING` 阶段终止，下一次启动时不得把旧文件升级为 `STOPPED`；旧文件保持不可导出并显示需要重新记录或人工处理的状态。心跳只能用于显示“服务可能失联”的诊断，不得作为导出资格。

重新开始记录前，服务清理上一条活动状态，创建新的文件名，并保留旧的 `ERROR`/未完成文件用于诊断但不作为导出候选。应用卸载仍由系统清除全部应用私有文件。

## 5. Android 可测试边界

新增无 Android 依赖的生命周期判定模型，输入状态、文件名、目录关系、解析结果和文件快照，输出可导出/拒绝及原因。Service 只负责传感器、GPS、writer 和状态持久化；UI 只显示判定结果并发起显式文档导出。

测试覆盖：

- `ACTIVE`、`STOPPING`、`ERROR` 状态拒绝；
- `STOPPED` 但文件名不匹配、路径越界、文件被替换和解析失败拒绝；
- 合法已关闭文件允许导出；
- 停止顺序最终写入 `STOPPED`；关闭异常写入 `ERROR`；
- 通知停止动作进入同一停止流程；
- 模拟导出不读取 `recordings`，真实导出不读取 `simulations`；
- 不新增 `addTestProvider`、`setTestProviderLocation`、Xposed/LSPosed 或传感器注入调用。

## 6. UI 行为

记录页显示明确状态和当前文件。只有 `STOPPED` 且解析通过时启用导出入口；`ACTIVE`/`STOPPING` 显示不可导出，`ERROR` 显示原因。导出菜单仍提供 CSV、JSON、GPX，并保留 `real_observation` provenance。

UI 刷新可以继续使用轮询展示状态，但轮询只影响显示，不参与导出资格判断。导出点击时重新执行完整判定，避免 UI 快照过期。
