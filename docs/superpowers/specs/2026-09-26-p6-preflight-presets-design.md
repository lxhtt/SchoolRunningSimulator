# P6 自检与参数预设设计

日期：2026-09-26
状态：已确认，实施中

## 目标

在模拟跑台开始前提供可读的运行前自检，并提供保守、可解释的参数预设。自检不读取真实 GPS，不调用系统注入 API；预设不包含个人校准结果，也不自动启动服务。

## 自检模型

纯 Kotlin `SimulationPreflight` 接收通知权限、模拟目录可写、当前历史可读和参数可行性四项输入，输出 `PASS`、`WARNING` 或 `BLOCKED` 的检查项及总体状态：

- 通知权限：缺失时 `BLOCKED`，因为后台/息屏进度不可见；
- 模拟私有目录：不可写时 `BLOCKED`；
- 现有历史：不可读时 `WARNING`，没有历史时视为通过；
- 参数：速度/手动步频/后段减速不可行时 `BLOCKED`；
- 系统注入边界：固定显示“未使用”，作为 `PASS` 的安全边界声明。

只有总体没有 `BLOCKED` 项时允许点击开始。诊断文本由 Android 资源本地化，模型不依赖 Android。

## 参数预设

模拟页提供三个按钮，仅更新当前表单：

- 轻松步行：1.4 m/s，自动步频，10 分钟，后段减速关闭；
- 稳定跑：2.7 m/s，自动步频，10 分钟，后段减速关闭；
- 节奏跑：3.5 m/s，自动步频，20 分钟，后段减速关闭。

用户之后仍可手动调整速度、时长、步频和减速。预设不会保存到真实记录目录、不会导出、不会启动服务。

## 波形复核工具

模拟历史现在提供只读波形复核：检查样本时间递增、速度/步频有限且非负，并展示样本数、时长、速度/步频范围和相邻样本最大变化。结果只描述模拟历史的数据连续性，不作为真实 GPS 或步频精度结论。


- JVM 测试覆盖缺失通知、不可写目录、不可行参数、历史警告、全通过组合和波形无效输入。
- 结构检查确认自检不引入 `addTestProvider`、`setTestProviderLocation` 或 Xposed/LSPosed。
- UI 仍保持应用私有 simulation history 与真实 recordings 隔离。
