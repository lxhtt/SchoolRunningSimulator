# P2 首版：应用内模拟跑台

## 范围

- `InteractiveSimulation` 在纯 JVM 中包装 `GaitEngine`，固定 0.1 秒步长；输入目标速度 0.8–5.0 m/s、时长 10–3600 秒。UI 提供 1–30 分钟选择。
- 目标速度低于 2.2 m/s 使用步行默认档，否则使用跑步默认档。步频和步长范围是工程默认参数，**不是个人校准结果，也不是普适生理界限**。个人 Apple Health 拟合不进入 APK。
- `SimulatorService` 是独立于 GPS 记录器的 `specialUse` 前台服务。运行时持有有时限的 CPU 唤醒锁，使用单调时钟每秒推进并刷新通知，不因应用退到后台或息屏自动暂停；暂停、停止或完成时释放唤醒锁。持续息屏更新通知会增加耗电量；通知展示时间、距离和步频，并提供暂停/继续/停止。
- 手动暂停冻结模拟时钟、距离与步数；恢复后接着推进。停止和自然完成保留最后一次摘要，服务退出。进程被系统杀死后不自动恢复，界面以心跳超时标记中断。
- UI 每秒读取应用私有状态快照；重新打开应用仍能看到正在运行的会话。未允许通知时不开放启动入口，以免后台进度不可见。

## 尚未实现

- 不读取真实 GPS、不修改系统定位、不发送模拟数据给第三方应用。
- 轨迹地图、曲线、语音、导出、区间/体征输入及个人校准档位尚未接到 P2 界面。记录器的 S7→S6 稳定段转换仍是独立待办。
- `specialUse` 是面向当前侧载测试的服务类型；尚未评估 Google Play 对该用途的审核资格，不以设备运行成功推断上架资格。

## 验收

1. CI 在 JDK 17/21 跑核心测试，Android lint 和 APK 构建通过。
2. 手机上授予通知权限后启动模拟，检查速度、步频、步数和距离随时间推进。
3. 息屏并将应用退到后台至少两分钟，检查通知仍在更新；从通知暂停、继续、停止，确认暂停阶段时间与距离不增加。
4. 重新打开应用，核对界面与通知的进度一致；模拟自然完成后通知消失，摘要保留。
5. 检查记录器仍使用独立 `location` 前台服务；拒绝通知权限时启动入口保持禁用。测试小屏、横屏、大字体和深浅色。
